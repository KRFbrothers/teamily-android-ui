Dua Gen AI — Android UI design package

Dua Gen AI — ek complete package: Dua AI, Dua Agent aur Dua Workspace. UI mein do modes hain: Dua aur Agent. Dua ek chatbot hai — simple chat, sawaal-jawaab, koi agent kaam nahi. Agent multitask karta hai, doosre agents ko control karta hai, aur naye agents bana sakta hai. Isliye Dua mode bilkul plain hai — khaali body + sirf "Ask Dua Gen AI…" composer, koi chat list nahi, koi search nahi, koi bottom nav nahi, agent ki ek bhi cheez nahi. Aur Agent mode me wo agents hain jinhe Agent control karta hai.

Neeche har frame me Dua | Agent toggle tap karein — poora screen switch hota hai. Palette Dua Gen AI ki hai: #087C45 primary, #42D982 mint, Lato. Reference ka purple #7C3AED aur blue #2563EB jaan-boojh kar nahi liye.

LayerKya karta hai
HttpTransport naya Ek-method seam. fun interface HttpTransport { fun execute(method, url, body): String }. Default UrlConnectionTransport asli HttpURLConnection chalata hai (koi library nahi); test apna fake deta hai aur socket ke bina poora remote source chala leta hai.
JsonHttpClient naya Wahi request code, ek jagah. Pehle Artifacts aur Memory dono apna-apna request() rakhte the — do copies ek hi rule ki, jo drift karti hain. Ab JsonHttpClient.request(method, url, body) ek hi implementation hai. Non-2xx par HttpStatusException → labelled IllegalStateException ("Artifacts request failed: HTTP 500"), isliye error abhi bhi batata hai kaunsi call fail hui.
RemoteArtifactsDataSource v32 Sirf apna hissa rakha. Endpoint (ArtifactsConfig) aur JSON shape — request mechanics ab shared client se. fetch() / add() / delete() sab client.request(...) par jaate hain.
RemoteMemoryDataSource v32 Wahi client, doosra endpoint. fetch() ka inline connection code hata diya — ab parseMemories(client.request("GET", baseUrl)). Dono sources ek hi JsonHttpClient instance share kar sakte hain.

08 · Shared repository engine

Ek engine, do repositories — load / refresh / add / delete ek hi jagah.

LayerKya karta hai
Identifiable naya Ek chhota contract. interface Identifiable { val id: String } — bas itna ki engine kisi bhi item ko id se delete kar sake. ArtifactItem aur MemoryItem dono ise implement karte hain.
RemoteDataSource<T> naya Data source contract. fetch() / add(item) / delete(id) — sab suspend, sab throw kar sakte hain. Repository exception ko Error state me badal deta hai, isliye source ko failure model karne ki zaroorat nahi, sirf report karne ki. ArtifactsDataSource aur MemoryDataSource isi ko extend karte hain (apna naam rakhte hue, taaki UI aur tests na badlein).
BaseRemoteRepository<T, S> naya Poora engine. MutableStateFlow state, isRefreshing, loadCount, aur load() / refresh() / add() / delete(). refresh() jaan-boojh kar Loading set nahi karta (list dikhti rehti hai), aur isRefreshing finally me clear hota hai. Concrete class sirf loadingState / loadedState / errorState / itemsOf / errorFallback deta hai.
ArtifactsRepository v33 Ab sirf state shape. BaseRemoteRepository<ArtifactItem, ArtifactsUiState> extend karta hai. Public API bilkul same — screen aur tests chhue nahi.
MemoryRepository v33 Wahi engine, doosra item type. BaseRemoteRepository<MemoryItem, MemoryUiState> extend karta hai — koi duplicate load/refresh/add/delete nahi bacha.
HttpClientProvider naya Ek shared client instance. object HttpClientProvider { val client } — dono remote sources isi par default karte hain (ek connection pool, ek config). Per-request label se error abhi bhi batata hai kaunsi feature fail hui.
